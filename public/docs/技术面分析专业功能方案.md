# 个股技术面分析 —— 专业功能发掘方案

> 结论先行：**系统里已经躺着一套 2130 万行、1888 只标的、107 个因子的因子库，但前端只用了其中 2 个因子。**
> 这不是"缺功能"，而是"挖出来的金子没被摆到台面上"。本方案分四层递进，建议**先做 L0 + L1**（低成本、直接可用），L2/L3 视反馈再上。

---

## 一、现状盘点（摸清家底）

### 1.1 数据资产（已实现，体量惊人）

| 资产 | 实测情况 |
|---|---|
| `factor_values` 表 | **21,277,419 行**，1888 个 ticker，**107 个因子** |
| 数据历史深度 | 1993-12-31 ~ 2026-09-29（真实历史，非仅 1 年） |
| 其中技术类因子 | **24 个**（见下），每个因子约 60-65 万行 |
| 个股池（monitoring=1） | 74 只 |
| 更新频率 | 每交易日 20:10 日更（个股池 + ETF 去重并集） |

**24 个技术因子**（`service/factor_desc.py::technical_fields`）：
```
动量：  mom_5/10/20/50, mom_composite, mom_acc, mom_risk_adj_5/10/20/50
波动：  vol_10/20/50, vol_composite
乖离：  bias_10/20/50, bias_composite

量能：  turnover_5/10/20, turnover_composite
```

### 1.2 前端实际用到多少？

| 页面 | 实际展示的因子 |

> **24 个技术因子里，有 20 个从来没被任何页面展示过。** 它们唯一的用处是塞进 LLM prompt 里当文本，人眼看不到。

### 1.3 后端"有引擎但没有出口"

| 能力 | 代码位置 | 是否被调用 |
|---|---|---|
| 多因子条件选股 | `FactorSelectorService.select_stocks_by_factors_asof` L129 | ❌ 全仓无调用点 |
| 因子时间序列 | `FactorValueService.get_stock_factor_series` L154 | ❌ 无 API 暴露 |
| 因子批量最新值 | `FactorValueService.get_latest_factor_values` L239 | ⚠️ 仅内部/选股用 |
| **因子相关的 REST 接口** | `routes/` 全目录搜索 | ❌ **一个都没有** |

### 1.4 关键技术约束（决定方案怎么做）

1. **无本地 K 线表** —— 日线每次实时打 `databull` SDK，约 365 天窗口。因子库是唯一落库的派生数据。
2. **因子是长表（EAV）** —— `trade_date + ticker + factor_name + value`，新增因子零迁移，但查询要按 `ticker+factor_name` 命中主键。
3. **两套"技术指标"并存且代码不共享** —— 前端 klinecharts 自带 MACD/KDJ/BOLL（浏览器现算，与后端无关）；后端 `factor_values` 是落库版。**同口径但两套实现，有漂移风险。**
4. **前端已有 klinecharts + ECharts 两个图表库**，可直接复用。
5. **无换手率/复权因子** —— `turnover_*` 是用 volume 均值近似，命名有误导性。

## 二、方案设计（四层递进）

### L0 · 因子看板（把已有数据摆上台面）—— 强烈建议先做

> 目标：让 24 个技术因子**第一次被人看见**。改动最小，收益最直接。

**新增后端接口（`routes/factor.py`，新建）**

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/factor/stock/{symbol}` | 该股全部技术因子最新值 + 中文名 + 分位数（在自身历史中的位置） |
| `GET` | `/factor/stock/{symbol}/series?names=mom_20,rsi_14` | 因子时间序列（复用已有 `get_stock_factor_series`，支持多因子） |
| `GET` | `/factor/catalog` | 因子字典（107 个因子的中文名/描述/分类，来自 `factor_desc.py`） |

**前端改动（`StockDetail.vue` 技术面 Tab 顶部新增 Card）**
- 因子分组卡片：动量 / 波动 / 乖离 / 量能 / 超买超卖 / 区间位置
- 每个因子显示：**当前值 + 历史分位条（0~100%）+ 中文名 + 一句话解释**
- 分位数上色沿用 A 股习惯（高=红、低=绿），超买/超卖/极端值加标签
- 支持点因子名 → 在下方 ECharts 画该因子近 250 日曲线

**为什么先做这个**：后端服务全是现成的，只差 3 个薄接口；前端复用现有卡片样式；把"黑箱 LLM 文字"变成"可核验的数字"。

---

### L1 · 技术面仪表盘（专业级研判面板）

> 目标：从"一堆数字"升级为"一眼看懂多空格局"。

**A. 趋势与均线系统**
- MA5/10/20/60/120/250 排列状态自动判定（多头/空头/纠缠 + 连续确认天数）
- 用现成的 `is_ma_bullish` 因子 + 实时算的均线，做**排列强度条**
- 价格相对各均线的乖离（复用 `bias_*`）

**B. 动量/波动象限图**（散点，X=动量分位，Y=波动分位）
- 四象限：强势低波（最佳）/ 强势高波（激进）/ 弱势低波（磨底）/ 弱势高波（危险）
- 该股当前落点 + 历史上落点轨迹，直观反映"风格漂移"

**C. 量价配合度**
- `turnover_*` + `closing_strength`（收盘强度，已算未用）合成"量价健康度"
- 识别：量价齐升 / 缩量回调 / 放量滞涨 / 地量地价

**D. 超买超卖热力**
- `rsi_14` + `52week_position` + `bias_composite` 三合一热度条
- 标注超买（>80）/ 超卖（<20）/ 中性区

**E. 关键位自动识别**（后端算）
- 支撑/压力：近期成交密集区 + 52 周高低 + 整数关口
- 用 ATR(14)（已算但未用）给出**动态止损位建议**（如 现价 - 2×ATR）

**F. 主力行为阶段时间轴**
- 复用 `main_force_behavior_phase`（1吸筹/2洗盘/3拉升/5出货初期/6出货末期）
- 画近 250 日阶段变迁时间轴，标注当前阶段持续天数（比单点标签信息量大得多）

---

### L2 · 因子雷达 + 横向对比（让因子"可比较"）

> 目标：解决"这个 RSI=65 到底算高算低？"的问题——需要参照系。

**A. 因子雷达图**
- 选 6~8 个核心因子，全部转成 **0~100 分位**
- 与"自身历史"或"同行业个股中位数"对比，双环叠加

**B. 个股 vs 基准对比**
- 该股 vs 沪深300 / 同行业指数：动量、波动、51周位置三线对比

**C. 行业内因子排名**
- 该股在所属行业中的各因子分位数排名（前 20% / 中位 / 后 20%）

**依赖**：需要行业成分股映射（`stocks.industry` 已有），是 L2 的主要工作量。

---

### L3 · 因子选股 / 回测打通（把"无出口引擎"接上）

> 目标：让 `select_stocks_by_factors_asof` 这个沉睡的引擎跑起来。

**A. 因子选股器页面**
- 条件构建器（因子 + 运算符 + 阈值，可多条件 AND）
- 后端直接用 `select_stocks_by_factors_asof`（已实现，只需套一层 `routes/factor.py`）
- 结果表格 + 一键加自选

**B. 技术信号扫描（替代/补充 LLM 定频分析）**
- 纯规则扫描：MACD 金叉 / RSI 超卖 / 均线多头初成 / 52周新高突破
- **零 token 成本**，可每日全池扫描（现在 LLM 版周一三五跑，还要花 token）

**C. 因子有效性回测**（可选，工作量大）
- 单因子 IC / 分层收益
- 需接 `backtest/` 模块

## 三、建议落地顺序与取舍

| 层级 | 工作量 | 价值 | 依赖 | 建议 |
|---|---|---|---|---|
| **L0 因子看板** | 小 | ★★★★★ | 无（服务全现成） | **立即做** |
| **L1 技术仪表盘** | 中 | ★★★★☆ | 无（部分需后端算关键位） | **第二批做** |
| **L2 雷达+横向** | 中 | ★★★☆☆ | 行业内映射 | 看反馈 |
| **L3 选股/回测** | 大 | ★★★★☆ | 回测模块 | 单独排期 |

### 三个"顺手修"的坑（建议一并处理）

1. **`atr_14` / `closing_strength` 有计算但没进 `factor_desc.py`** → 补描述，才能被 L0 目录正确展示。
2. **`turnover_*` 命名误导** → 它其实是"成交量均值"不是"换手率"（无流通股本）。建议在目录里把中文名改成"量能活跃度"或补真实换手率数据源。
3. **前端 klinecharts 指标 vs 后端因子口径不统一** → 至少加注释/文档说明，长期建议前端改读后端因子，消灭两套实现。

## 四、最小可行起步（如果只想先要一个）

**L0 因子看板**：3 个后端接口（约 150 行）+ `StockDetail.vue` 技术面 Tab 加一张分组卡片（约 200 行）。**无新表、无迁移、无 job 改动**，全部复用现有 `FactorValueService` / `factor_desc.py`。做完即可让 24 个因子第一次出现在页面上。
